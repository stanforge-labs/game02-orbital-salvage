# PHONE TEST

1. ПК и телефон → один Wi-Fi.
2. Дважды нажать `PLAY_ON_PHONE.bat` в корне проекта.
3. Сканировать QR из терминала или открыть `PHONE_QR.png`.
4. Повернуть телефон горизонтально.
5. Проверить touch, звук, HUD, плавность полёта.

Окно владельца сервера оставить открытым. ENTER останавливает его сервер.
Повторный запуск использует уже работающий PHONE TEST сервер; закрытие второго
окна его не останавливает. Чужие процессы и старый localhost-сервер не завершаются:
если 4237 занят ими, выбирается 4238…4256. Всегда использовать показанный PHONE URL.

## Сборка и зависимости

`tools/phone/current-build.json` указывает на действующий PC launcher
`PLAY_WORLD20.ps1`. Путь берётся из его build assignment: `exports/worldart20`.
Файлы отдаются непосредственно из этой папки — второй копии нет. При отсутствии
экспорта запускается существующий export-core над текущим game.json. Существующий
экспорт не пересобирается автоматически: он совпадает с тем, что открывает PC launcher.
При переходе на новый PC launcher обновить только current-build.json.

Нужен Node.js (он уже используется проектом). На первом запуске npm ci устанавливает
зафиксированный `qrcode@1.5.4` (MIT, https://github.com/soldair/node-qrcode), далее QR
генерируется полностью локально, без интернет API. Lockfile фиксирует зависимости;
install scripts отключены. PNG локальный, не коммитится. `jsqr@1.4.0` (Apache-2.0,
https://github.com/cozmo/jsQR) — только dev-зависимость для независимой проверки QR.
Для QA: `npm ci --prefix tools/phone --ignore-scripts`, затем
`node tools/phone/qa.js <LAN_IP>` при остановленном PHONE сервере.

Никаких изменений игры, SDK, рекламы, сохранений или production cache.
Новый LAN origin имеет отдельное браузерное сохранение — это штатная изоляция
браузера; прогресс ПК автоматически на телефон не переносится.
DEV → MOBILE TEST MODE по-прежнему является эмулятором, не реальным телефоном.

## Troubleshooting

- **Страница не открывается:** проверить актуальный PHONE URL и открытое окно
  сервера. Loopback 127.0.0.1 работает только на самом ПК.
- **Windows Firewall:** локальный LAN GET не доказывает доступ другого устройства.
  Если телефон не подключается, терминал показывает точную команду администратора:
  только Node executable, выбранные порт/IP/интерфейс и RemoteAddress LocalSubnet.
  Команда не выполняется автоматически. Обратная команда удаления тоже выводится.
  Не отключать Firewall. При смене IP/порта старое правило не подходит.
- **Разные сети / guest Wi-Fi:** оба устройства должны быть в одной LAN, без
  client/AP isolation. Гостевая сеть может запрещать связь даже при похожем SSID.
- **Неправильный LAN IP:** выбирается физический активный интерфейс с gateway и
  наименьшей метрикой. VPN/виртуальные интерфейсы исключены. При двух LAN можно
  запустить `powershell -File tools/PLAY_ON_PHONE.ps1 -LanIP 192.168.1.35`.
- **Порт занят:** чужой процесс сохраняется, порт автоматически повышается.
- **Старая версия:** PHONE сервер отдаёт файлы с no-store/no-cache. Перезагрузить
  вкладку; убедиться, что сама PC-сборка экспортирована заново. При обновлении
  экспорта во время игры перезагрузить телефон после завершения сборки.
- **Звук:** сначала коснуться игры; браузеры блокируют autoplay. iOS mute/audio
  policies и реальную производительность проверять на самом устройстве.

Это LAN-инструмент без TLS/авторизации: использовать только доверенную домашнюю
сеть, не публиковать порт в интернет. Он отдаёт только браузерный export, не проект.
